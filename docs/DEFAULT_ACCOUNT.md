# 默认账号与前台会话

## 用户确认的行为

- 每个已配置 App 独立选择 Base 或任意已有账号作为默认；未设置时关闭，旧配置升级后保持关闭。
- 从桌面、最近任务、通知等外部入口打开目标 App，或真正离开后再次回到前台，自动进入默认账号。
- 从 Slice 内点选账号并启动，允许本次前台会话使用所选账号；不能在其启动后立即被监听器切回默认。
- App 自己发起的内部页面跳转（包括新进程或新任务）、临时拍照、文件选择、支付、权限弹窗及锁屏返回不结束这次会话。这些临时流程中的系统进程回收不结束会话。按 Home 或切到独立的其他 App 则结束会话。
- 自动切换复用 Runtime 的停止、CE/DE 成对挂载、验证和提交事务，切换后从默认账号首页重新启动。跨账号不承诺保留旧通知的页面和回调。
- 设置默认账号只保存策略，下次符合条件的前台进入时生效，不主动拉起后台 App。
- 删除默认分账号前明确提示，删除成功时同时关闭自动回默认。失败或中断未删除时保留原设置。
- 自动切换与手动切换、备份和恢复共用事务边界；不得在 account-I/O lease 内切换。

## 实现与验证边界

策略与账号一起存入 Runtime aggregate。Manager 负责选择和展示；KernelSU Runtime 负责目标 App 的前台观测和会话判定。不能用 Slice 自身的 onResume 代替目标 App 监听。

系统事件观测需要以当前 Android 17 真机输出与主机回归测试为依据。只有拿到对应设备行为后才将场景标为已验证；无观测或无法识别时不得把猜测写成验收通过。

本功能改变 wire，需要 Manager 与 KernelSU 模块成对升级；APK 保持现有固定 Release 签名和 applicationId，以覆盖安装保留配置。
