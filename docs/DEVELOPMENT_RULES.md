# UClone Slices V2 开发约束

这些规则用于保护已经跑通的切换链路。它们约束行为、依赖和证据，不用文件行数、目录数量、覆盖率或循环次数代替代码质量。

## 1. 先取证，后修复

- 真机或环境问题先增加只读探针，记录版本、输入、PID、socket、挂载、RPC、聚合状态和原始错误。
- 可以在主机确定复现的问题，先写一个稳定失败的最小测试；这个测试就是可执行探针。
- 探针没有命中假设时，只增强探针，不修改生产行为。
- 修复后必须使用同一探针或回归测试证明故障路径已经消失。
- 无法自动化的行为写入真机验收清单，并在验收完成前保持“候选修复”状态。

## 2. 只扩展完整产品链路

当前候选版 wire 固定为十三个操作和五个错误码。新增命令、字段、响应或错误码必须在同一个变更中具备：

1. 明确的用户操作。
2. Rust 端到端用例。
3. 共享协议 fixture。
4. Kotlin 消费测试。
5. 真实 UI 入口。

缺少任意一项就不进入 wire。生产代码没有读取点的公共字段直接删除。

## 3. 保持依赖方向

- `PackageAggregate` 是唯一业务状态。
- Use Case 完整编排保存意图、停止 App、CE/DE 操作、验证、提交和恢复。
- Manager 只发送用户意图并消费结果，不编排挂载步骤。
- 协议层只做 wire 转换，不拥有业务判断。
- KernelSU Shell 只负责启动和验证 Runtime transport，不判断槽状态。
- Runtime 内部只保留 `PackageStore`、`SlotStorage`、`AndroidOps` 三个 I/O seam；没有第二个真实实现需求时不增加新接口。

## 4. 保持事务边界

- 创建、激活、删除、取消配置和重新绑定先持久化带上下文的意图，再产生副作用。重新绑定按“验证 UID/签名和槽对 → 备份元数据 → journal → 停止 App → Base → 刷新 APK 身份 → 恢复活动槽 → 提交”执行，不删除槽、不启动 App。
- 桌面绑定只接受完整的非 Base CE/DE 槽对；替换或解除绑定不改变任何槽数据，删除已绑定槽成功后才清除绑定。
- `activate_desktop_shortcut` 必须在一次 Runtime 锁内确定目标并复用现有激活事务；启动失败时恢复 previous，不能提交半切换状态。
- CE/DE 是一个不可拆分的槽对；不能发布或提交半个槽。
- 失败必须恢复 previous，或者保留足以让下一次请求继续收敛的生命周期上下文。
- 聚合、真实挂载视图和 App 进程视图必须分别验证，不能互相代替。
- 同包名、同 UID 且签名谱系兼容的 APK 身份变化可以无损接管；没有签名 sidecar 的 0.1.6 配置只有在 UID 相同且用户输入“绑定”确认后才能接管。
- UID 或签名不一致使用 `identity_mismatch`，不完整槽对、非 Ready 聚合和真实视图异常使用 `state_conflict`；两类失败都必须零删除。
- `enroll reset:true` 在 0.1.7 Runtime 中始终拒绝。唯一危险清理入口是用户明确选择“取消配置并删除分空间”。

## 5. 保持 Manager 单向状态

- 所有操作从单一 `UiIntent` 入口进入。
- Intent 到达时冻结包名、槽名、seed 和 slot ID。
- 同一时刻只允许一个 Runtime 操作；busy 时丢弃新操作，不排队。
- transport failure 与 Runtime wire error 分开处理，不能用业务失败表示断线。
- ViewModel 不读取 Android 挂载或持久化细节。
- Manager 与 Runtime 版本不一致时只允许读取已有快照，所有改变状态的 Intent 必须在 ViewModel 入口拦截。
- 首页空间展开状态只属于 Manager 本地偏好，不进入聚合或 wire。
- 桌面状态投影只保存 Runtime 已确认的绑定槽、活动槽和显示名；Provider 查询不得调用 `su`，切换只能由签名权限保护的前台 Service 发起。

## 6. 不增加无依据设置

- 数值设置必须来自平台约束、产品规则、已验证工具链或可复现测量，并记录在 `SETTINGS_PROVENANCE.md`。
- 不设置文件长度、目录数、覆盖率、固定压力次数、经验重试次数或经验超时作为质量门禁。
- 同一设置只保留一个权威来源；重复声明由脚本检查一致性。

## 7. 变更与提交

- 一个提交只表达一个可验证的行为或一次仓库收敛。
- 不把设备专用热修脚本保留为产品能力；通用只读诊断和通用恢复工具可以保留。
- 不顺手重构与当前证据无关的代码。
- V1 只作为行为和视觉参考，不迁移旧 ViewModel、协议编排或未提交工作区。

## 8. 完成条件

行为变更只有在以下条件全部满足后才算完成：

- 探针或失败测试明确复现原问题。
- 修改后的同一证据转为通过。
- 受影响的 Rust/Android/Shell 主机门禁通过。
- 需要真机才能观察的表面已按 `DEVICE_QA.md` 和 `DESKTOP_SHORTCUT_QA.md` 验收。
- 文档、版本和产物来自同一个提交。

真机门禁尚未完成时可以交付候选包，或在用户明确授权后推送清楚标注的预发布基线；不能把设备行为写成已经确认，也不能提升为正式 Release。
